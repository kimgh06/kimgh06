일한 곳

오앤디랩, 루트북

2026년 7월 ~ 지금

기업이 더 낸 세금을 경정청구로 돌려받게 해 주는 서비스입니다. 홈택스, 은행, 카드사에서 자료를 가져오는 조회기부터 백엔드와 웹까지 만들고 있습니다.

환급 진단 한 번에 5분 30초

재 보니 부가세 115초, 법인세 215초였고, 법인세 쪽은 서식 65장을 장당 2.4초씩 받느라 156초를 쓰고 있었습니다. 그런데 판정에 실제로 읽는 서식은 세 장뿐이었습니다. 진단 대부분은 신청으로 이어지지 않으니 미리 받아 두는 건 버리는 시간이었습니다.

판정용 3종과 탐지용 3종만 받고 나머지는 신청이 들어왔을 때 받게 바꿨습니다. 이때 안 받은 서식을 "미제출"로 처리하던 코드가 있어서, 그대로 뒀으면 "이 신고는 공제를 신청하지 않았다"는 거짓 판정이 나올 뻔했습니다. 받음, 있지만 안 받음, 애초에 없음 세 갈래로 나눴습니다. 같은 회사로 244초에서 123초가 됐습니다.

은행 인증서 로그인 33초

서명창과 보안 키패드를 고정 시간만큼 기다리고 있었고, 로그인 페이지의 보안 모듈이 준비되기 전에 누르면 서명창이 아예 안 떴습니다.

고정 대기를 화면 변화 감지로 바꾸고, 쉬는 워커가 로그인 페이지를 미리 열어 두게 했습니다. 11초가 됐습니다. 은행 세션이 8~16분 방치하면 끊기는 것도 실측으로 찾아서, 끊기면 자동으로 다시 로그인하게 했습니다.

누가 고객사 원본을 받아갔는지 답할 수 없었음

접근은 막고 있었지만 기록은 안 남겼습니다. 회계법인 직원이 어느 고객사의 홈택스 원본을 언제 몇 건 받아갔는지 물어도 답이 없었습니다.

모든 쓰기는 DB 트리거로, 읽기는 요청 단위로 남겼습니다. 이 DB는 읽기가 쓰기의 36배라 쿼리마다 남기면 감사 로그가 본업보다 커지기 때문입니다.

운영 DB 백업이 하나도 없었음

cron도, 덤프 파일도 없었습니다.

30분마다 서버와 오브젝트 스토리지 두 곳에 백업하고, 받은 백업을 격리 컨테이너에 복원해서 행 수가 운영과 같은지 확인했습니다. 알림을 붙이다 보니 Slack 웹훅이 예시 값 그대로라 컨테이너 다운이나 디스크 알림이 한 번도 안 가고 있던 것도 찾아서 고쳤습니다.

더빌딩솔루션

2026년 1월 ~ 7월

임대관리 SaaS를 3인 팀에서 만들었습니다. 온보딩 없이 들어가서 청구, 정산, 전자계약, 입주민 포털까지 11개 영역을 맡았습니다.

계약마다 외부 전자계약 수수료

외부 전자계약 서비스를 써서 건당 3천~1만 원이 나가고 있었고, 가계약, 전자계약, 입주, 퇴실 정산이 서로 이어지지 않아 단계마다 손으로 옮겨야 했습니다.

전자계약을 직접 만들었습니다. 임대인, 중개사, 임차인 순서로 서명하고 문자로 본인 확인을 합니다. 가계약에서 버튼 하나로 전자계약을 만들고, 퇴실 정산까지 한 흐름으로 이었습니다.

돈이 틀리게 나갈 수 있던 곳

은행 거래 내역을 지우면 입금 기록까지 같이 사라지는 구조였고, 연체 판정 기준이 화면마다 달라 연체가 아닌 입주자에게 연체 알림이 갈 수 있었습니다.

거래를 지워도 입금 기록은 남게 하고, 연체 기준을 하나로 맞췄습니다. 청구서 금액 계산 오류도 같이 고쳤습니다.

로그인 없이 열려 있던 API

API 7개가 인증 없이 열려 있었고, 로그인 페이지는 외부 주소로 리다이렉트시킬 수 있었습니다.

인증을 걸고 리다이렉트 대상을 막았습니다. 흩어진 fetch와 axios 호출을 하나의 클라이언트로 모아 토큰이 만료되면 자동으로 로그아웃되게 했습니다.
