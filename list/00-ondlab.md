현재 재직 중인 회사입니다. 기업이 더 낸 세금을 경정청구로 돌려받게 해 주는 플랫폼 **루트북**을 개발하고 있습니다. 주력 저장소는 `RTBK-AI/bookkeeping_data_plan`(비공개)이며, 2026.07.25부터 약 265개를 커밋했습니다. 대부분 9월에 몰려 있고, 기능은 PR 리뷰를 거쳐 반영합니다.

## 구성
| 모듈 | 역할 |
|---|---|
| `codes/api` | 홈택스·근로복지공단 조회기 — 세션당 워커 게이트웨이, Redis 세션, 순수 HTTP 직접호출 |
| `codes/bank` · `codes/cards` | 은행 7곳과 카드사(BC·신한) 인증서 로그인, 계좌·거래내역 조회 |
| `codes/backend` | NestJS + Kysely + PostgreSQL — 워크스페이스, 경정청구 케이스, 감사 로그, 약관 |
| `codes/web` | React Router 7 웹 — 경정청구 대시보드, 가입·인증서 등록, 멤버 초대 |
| `codes/monitoring` | Grafana 운영·성장 지표, Slack 알림 |

## 한 일
- **세무 데이터 수집**
  - 홈택스 로그인을 구현하고 조회 방식을 순수 HTTP로 바꿨습니다
  - 표준재무제표, 법인세 신고도움, 환급금, 고지·체납 내역, 지급명세서를 조회합니다
  - 근로복지공단 급여와 4대보험 조회를 붙였습니다
- **은행·카드 조회**
  - 7개 은행의 로그인 방식을 조사했고, 경남은행 인증서 로그인과 거래내역 API를 구현했습니다
  - 은행 로그인을 33초에서 11초로 줄이고, 워커 풀 누수와 세션 만료 시 자동 재로그인을 해결했습니다
- **경정청구 핵심**
  - 예상 환급액을 산출합니다. 법인세 R&D·통합투자 공제를 반영하고, 검산과 최저한세 서식 파싱을 넣었습니다
  - 환급진단을 A/B/C 세 단계로 나누고, 근거자료 수집과 케이스 진행 상태를 관리합니다
  - 법인세 진단 시간을 244초에서 123초로 줄였습니다 (서식 13종 중 필요한 6종만 받게 함)
- **전자세금계산서**
  - 발급·수정발급 API를 만들고, 일괄발급 화면을 조사했습니다
- **계정·워크스페이스**
  - 아이디, 공동인증서, 네이버·카카오 소셜 가입을 지원합니다
  - 멤버 초대, 법인카드 관리, 인증서 다중 등록, 계정 복구를 만들었습니다
- **운영 기반**
  - 모든 쓰기와 읽기를 감사 로그로 남깁니다
  - DB를 30분마다 백업하고, 실패하면 Slack으로 알립니다
  - Grafana 대시보드로 가입·신청·취소·세션 지표를 봅니다
  - 개인정보처리방침과 이용약관을 게시했습니다
- **설계 문서**
  - 세법·개인정보·세무사법 검토, 데이터 스키마(dbml), 액션 시나리오, 분개장 설계, AI 모델 조사를 문서로 정리했습니다
